## Performance and measurement review

The paired microbenchmarks use five fresh processes on Apple M5, 10 logical CPUs, 16 GiB RAM, Darwin 25.5.0 arm64 and Node 24.21.0. For 20000 warm accesses over 64 keys and 1 KiB structured values, fail-safe-disabled lookup rises 30.46%; fail-safe-enabled lookup rises 21.12%. The configured family bootstrap policy flags both. Queried membership at N=8192 improves 99.83%, 1024-active-key follower registration improves 97.52%, and 2048 distinct promotions improve 65.02%. Accepted 1000/10000/100000-caller herds still perform one load but take longer and retain more waiter-associated heap. Strict validation, ownership and bounded coordination remain necessary; these measurements do not justify a universal speedup claim. [Complexity evidence](03-complexity-report.md), [paired comparison](10-before-after-comparison.md).

The CI-equivalent quick workload independently compares seven repeats against the original commit with the identical dependency lock. It flags lookup +31.7%, lookup-stale +24.1%, 1000-caller herd +34.6% and 10000-caller herd +79.6%; the gate exits 1 after successful harness execution. Five- and seven-repeat raw comparisons remain separate. [Before](raw/ci-before.json), [after](raw/ci-after.json), [provenance](raw/ci-provenance.json), [workflow](../.github/workflows/performance.yml). Hosted GitHub Actions execution and release branch protection are NOT MEASURED.

Independent HTTP load generation uses two cache processes, one controlled origin and a separate generator, 1 KiB payloads and seeded skew over 64 keys. The added 10000-offered-RPS warm phase has three one-second repetitions per version: median successful rate 9965.60 → 9974.84 RPS, p99 6.017 → 6.851 ms and worker CPU per million requests 32848 → 38204 ms. All warm phases have zero errors, timeouts, client drops and observed freshness violations. The p99 ranges overlap; these short demand-limited samples establish neither higher maximum capacity nor a statistically proven tail improvement. [Original high-rate data](raw/e2e-before-high.json), [revised high-rate data](raw/e2e-after-high.json).

Paired cold-hot-key lease cases issue one origin request across two workers in both versions; disabling the lease issues two. Stale-if-error serves responses but still sends nearly one origin request per failed-origin caller in this workload. It is not sufficient origin rate protection by itself. The HTTP burst uses a finite socket pool and includes client queue delay; it must not be presented as an equal number of simultaneous server-side followers. Open-loop timing includes dispatch lag, and unsent arrivals are counted separately rather than hidden from the error rate. [E2E results](08-benchmark-results.md).

Memory measurements distinguish forced-GC process deltas, OS high-water RSS, sampled allocations and directly owned heap-snapshot nodes. For twenty open empty stores, the midpoint forced-GC heap-plus-external process delta falls from 4507364 to 110160 bytes, a 97.56% reduction; held-closed reference retention also falls. This does not imply a comparable total RSS decrease. One-entry compressed 10 MiB deltas can be negative because of GC/runtime noise, and remain labeled measurements. Exact allocation count, precise dominator-retained entry size, temporary allocation peak and native fragmentation are NOT MEASURED. The final 30-second smoke records no assertion failure and releases the ledger to zero; it does not establish hours-long stability.

## Remaining work before an unqualified release claim

1. Establish byte/origin/follower bounds and a conditional-publication or explicitly weaker source-consistency contract for the Worker/KV integration. Generic custom adapters need enforceable publication capability rather than ownership-only unlock.
2. Verify actual Redis Cluster/failover and authoritative source-version or durable invalidation recovery in the intended isolated topology. Observed subscriber recovery does not detect every lost publisher event, and paginated pattern invalidation is not an atomic namespace transaction.
3. Provision long-duration memory/overload recovery runs and tenant-aware shared-origin limits. Align the supported Node/dependency matrix and complete the required documentation build within a declared resource budget.
4. Review the measured safety costs under the stated performance gate. Keep correctness protections while pursuing only profiling-supported allocation/CPU reductions and preserving their regression cases.

The [prioritized backlog](11-future-architecture.md) supplies acceptance evidence for this work. Failed gates stay active regardless of favorable throughput or individual test counts.
