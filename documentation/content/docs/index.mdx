## Introduction

**LazyLayers** is a **production-grade hybrid caching framework for Node.js**, designed to deliver sub-0.1ms in-memory speeds while keeping multi-server clusters in distributed lockstep over an event bus. It consists of multiple coordinated layers:

<CardGroup cols={2}>
  <Card title="L1 In-Memory Store" icon="bolt" href="/docs/concepts/layers">
    Nanosecond in-process LRU cache. Delivers local-memory read speeds with bounded entry counts and automated heap eviction.
  </Card>

  <Card title="L2 Shared Remote Store" icon="database" href="/docs/concepts/layers">
    Shared cluster tier backed by Redis. Stores binary MessagePack payloads with size-tiered LZ4/Zstd compression (33%–92% wire savings).
  </Card>

  <Card title="Invalidation Event Bus" icon="tower-broadcast" href="/docs/guides/event-buses">
    Propagates deletions (`del`, `pattern`) and lazy value priming (`set`) across instances over Redis Pub/Sub, RabbitMQ, or NATS.
  </Card>

  <Card title="Observability Suite" icon="chart-line" href="/docs/guides/observability">
    Live real-time dashboard at `/__lazylayers`, Prometheus scrapable endpoint, and telemetry event diagnostics stream.
  </Card>
</CardGroup>

<Note>
  **Want to understand the system design?** Read our in-depth [System Design & Architectural Reading Path](/docs/learn).
</Note>

## Core Mechanics

- **Read-Through Lazy Loading (`getOrSet`)**: Nothing is fetched until requested. On a cache miss, exactly one process runs the database loader, writes the result to L1 and L2, and broadcasts it across the event bus to prime peer L1 caches.
- **Thundering Herd Stampede Protection**: In-flight Promise deduplication coalesces 10,000 concurrent callers for a cold key into a single database execution.
- **Fail-Open Resilience & Circuit Breakers**: If Redis or your message broker becomes slow or unreachable, traffic degrades gracefully to L1 RAM and origin database queries without throwing 500 errors.
- **Self-Echo & Race Condition Filtering**: Every server carries a unique cluster `source` identity and monotonic generation counter to discard out-of-order writes and ignore its own broadcast events.

## Installation

LazyLayers requires **Node.js 20 or 22+**.

<CodeGroup>
```bash title="npm"
npm install lazy-layers-cache ioredis
```

```bash title="pnpm"
pnpm add lazy-layers-cache ioredis
```

```bash title="yarn"
yarn add lazy-layers-cache ioredis
```

```bash title="bun"
bun add lazy-layers-cache ioredis
```
</CodeGroup>

<Tip>
  `ioredis` is optional if you only need an in-process L1 LRU cache. Add `amqplib` or `@nats-io/transport-node` when using RabbitMQ or NATS event buses.
</Tip>

## Quickstart Example

Create your hybrid cache with L1 in-memory storage, shared L2 Redis, and cross-instance Pub/Sub invalidation:

```ts title="cache.ts"
import Redis from 'ioredis';
import { LazyLayersCache, RedisStore, RedisEventBus } from 'lazy-layers-cache';

interface User {
  id: string;
  name: string;
  plan: 'free' | 'pro';
}

const redis = new Redis(process.env.REDIS_URL || 'redis://127.0.0.1:6379');

// 1. Invalidation Event Bus: Keeps every instance in sync
const eventBus = new RedisEventBus(redis, 'cache:invalidations');

// 2. Hybrid L1/L2 Cache
export const cache = new LazyLayersCache<string, User>({
  levels: {
    L1: { maxEntries: 10_000, ttlMs: 60_000 },
    L2: { ttlMs: 300_000 },
  },
  l2: new RedisStore<User>(redis, { prefix: 'users:' }),
  eventBus,
  source: process.env.INSTANCE_ID || `node-${process.pid}`,
  broadcastSet: true, // Prime peer L1 caches when a loader resolves
});
```

### Reading and Mutating Data

```ts
// 1. Read-through: Loads from DB on miss, writes L1+L2, and primes peers
const user = await cache.getOrSet(`user:${id}`, async () => {
  return await db.users.findById(id);
});

// 2. Mutation: Drops the key across all layers and broadcasts to all servers
await db.users.update(id, { plan: 'pro' });
await cache.delete(`user:${id}`);

// 3. Pattern Invalidation: Drops all matching keys across the entire fleet
await cache.deleteByPattern('users:*');
```

## FAQ & Common Questions

<AccordionGroup>
  <Accordion title="What happens when Redis or the message bus goes down?">
    LazyLayers operates on **fail-open resilience**. If Redis or your event bus disconnects or fails:
    1. Reads degrade automatically to in-memory L1 cache or your database loader.
    2. Built-in circuit breakers trip to stop queueing work against unresponsive backends.
    3. Stale fallbacks serve the last-known value during upstream outages to prevent downtime.
  </Accordion>

  <Accordion title="How does in-flight deduplication stop thundering herds?">
    When multiple concurrent requests ask for the same expired or uncached key simultaneously, LazyLayers attaches all subsequent callers to the single in-flight Promise of the first caller. Exactly **one** database query is executed, and all callers receive the resolved result.
  </Accordion>

  <Accordion title="Which event bus transport should I choose?">
    - **Redis Pub/Sub**: Best for low-overhead setups where Redis is already part of your infrastructure (at-most-once delivery).
    - **RabbitMQ**: Best when durable message delivery with exchange routing (topic/fanout) is required.
    - **NATS Core / JetStream**: Best for ultra-high throughput microservice architectures.
  </Accordion>

  <Accordion title="How do I inspect live cache performance and memory?">
    Enable the built-in observability dashboard by passing `observability: true` (or mounting `cache.handler`). You can visit `/__lazylayers` in development/staging to inspect live L1 entries, Redis L2 memory, compression ratios, and real-time SSE invalidation telemetry.
  </Accordion>
</AccordionGroup>
