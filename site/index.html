The problem

Your cache is mostly
punctuation and repeated keys.

Cache a thousand user records as JSON and you store the string "firstName" a thousand times. Every number becomes a decimal string. Every value gets wrapped in quotes, braces and commas.

Redis charges you for all of it — memory, network transfer, and replication, on every replica.

The serializer

Three encodings.
Chosen per payload, at write time.

Every buffer carries a 4-byte prefix naming its own format, so reads stay uniform and you can change the write policy without migrating a single key.

Compression that refuses to waste your CPU

gzip is only attempted above 64 kB, and the result is only kept if it saves at least 15%. Feed it a large blob of random bytes and it will decline to compress rather than burn cycles for a rounding error.

  • Self-describing buffers. The 4-byte prefix means a single read path decodes every format.
  • Corruption-safe. A truncated or damaged buffer returns null instead of throwing into your request path.
  • Debuggable on demand. Set CACHE_FORMAT=json and read your cache with redis-cli again.
  • Null-safe. null and undefined round-trip through a packed sentinel that never leaks into your values.

Architecture

One instance pays for the load.
Every peer gets the result.

The first instance to lazily load a key broadcasts it to every peer, so their L1 warms without a second loader call. Deletes and wildcard wipes fan out the same way.

L1 · in-process LRU

Live objects, no serialization, nanosecond reads. Backed by lru-cache. Works with zero infrastructure.

L2 · Redis

Shared across instances, holding compact MessagePack buffers. Fails open — a Redis outage degrades to L1 instead of erroring.

Event bus

Redis Pub/Sub, RabbitMQ, NATS core, or NATS JetStream for durable, replayable invalidation with explicit acks.

Stampede protection

In-process inflight dedupe collapses concurrent same-key loads. Add a Redis-backed distributed lock to extend it across instances.

Live observability

Opt-in dashboard with per-key serialized-vs-in-memory sizes, a nested key explorer, and a live SSE event feed.

Prometheus + OTel

Built-in /metrics with bounded cardinality — never labeled by cache key — plus a diagnostics_channel telemetry stream.

Usage

A small API that grows
into a distributed one.

Start in-process. Add Redis when you outgrow one instance. Add a bus when you outgrow one region.

cache.ts
import { LazyLayersCache } from 'lazy-layers-cache';

const cache = new LazyLayersCache({ ttlMs: 60_000 });

// Lazy load. Concurrent callers share one loader call.
const user = await cache.getOrSet(`user:${id}`, () =>
  db.users.findById(id)
);
cache.ts
import Redis from 'ioredis';
import { LazyLayersCache, RedisStore } from 'lazy-layers-cache';

const redis = new Redis(process.env.REDIS_URL);

const cache = new LazyLayersCache({
  l2: new RedisStore(redis, { keyPrefix: 'app:' }),
  ttlMs: 300_000,
});

// Values are msgpack-encoded on the way into Redis.
// A Redis outage degrades to L1 — it does not throw.
cache.ts
import { LazyLayersCache, RedisEventBus } from 'lazy-layers-cache';

const bus = new RedisEventBus(redis, 'cache.invalidate');
await bus.connect();

const cache = new LazyLayersCache({
  l2, eventBus: bus,
  source: process.env.INSTANCE_ID,   // stops self-loopback
});

await cache.delPattern('user:*');  // fans out to all peers
cache.ts
const cache = new LazyLayersCache({
  l2,
  observability: {

  },
